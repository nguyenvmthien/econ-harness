Read `PLAN.md`, `LOG.md`, `ae-design`, and the applicable `ae-methods` playbook. `$ARGUMENTS` narrows PLAN §9 IDs or script groups; by default use relevant main and robustness rows. Require `output/logs/data_quality_report.md` to say PASS or PASS WITH CAVEATS and `data/analysis.rds` to exist; otherwise stop and direct the user to `/ae-data`. If §9 is empty or lacks a needed main model, propose candidate relations from PLAN §1–8 and, before running anything, append one §9 row per model with an `EXP` ID (EXP1, EXP2…); its Item states outcome, key regressor, FE/controls, SE/cluster level and sample, Type, `Script → output file`, and Status `planned`. These rows are EXPLORATORY under the `/ae-estimate` contract; never present them as locked. If PLAN §1–8 cannot define a candidate, ask once instead of guessing variables.
If `$ARGUMENTS` includes `output/logs/phacking/<run-id>.md` and a candidate ID, read that report **and** its result RDS and scratch script; treat the candidate as a lead selected after searching all logged attempts. Map it to new exploratory §9 IDs without erasing earlier searches, copy the search breadth and contrary/failed cells into `## Variant set` and `## Evidence matrix`, and run fresh defensible checks. A low p-value from the search never counts as independent validation or as a pre-results hypothesis.
The `/ae-phacking` handoff also requires `<run-id>.grid.csv`: match candidate ID and every declared field (`source_path`, `source_object`, `outcome`, `outcome_role`, `exposure`, `exposure_role`, `term`, `proxy_target`, `endogenous_regressor`, `instrument`, `estimator`, `controls`, `fe`, `transform`, `subgroup`, `timing`, `sample_rule`, `se_method`, `clusters`, `declaration_timing`, `variation_type`, `variation_source`, `assignment_rule`, `treated_exposure`, `comparison_group`, `estimand`, `identifying_assumption`, `validation_needed`, `diagnostics`) across grid, result RDS and report. Keep design-only variation leads visible as unverified; any `not-run` row means incomplete model coverage. A mismatch means stop rather than testing the wrong direction.


1. **Declare variants, then run them.** Create `output/logs/hypothesis_reframe.md`. Under `## Variant set`, list for each candidate the baseline §9 ID and every defensible robustness/diagnostic variant planned for this pass (FE/controls, measurement, sample, SE/inference, placebo, pre-trend/reverse-causality check as applicable) with a one-line rationale, before reading any variant result. A variant added after results were seen is allowed but tagged `added-after-results` with its reason. Then follow the `/ae-estimate` execution contract: implement missing models and execute the selected scripts from the project root (`Rscript <script>`), including relevant `R/04_robustness.R` or the equivalent PLAN script and dependencies. Under `## Run log`, append one row per model actually run in this pass, never removing rows: `run | §9 ID | script → output | outcome ~ regressor | change vs baseline | N | estimate (SE) or error | status (done / failed / not-produced) | declared or added-after-results`. Read estimates from fitted models/`modelsummary` outputs, not prose; do not call an old table a fresh run. If a declared variant cannot run, keep it in the log with its error and treat it as unresolved evidence.
2. **Classify from the full run log.** Under `## Evidence matrix`, per candidate cite the supporting and contradicting run-log rows and report the estimate range in economically meaningful units, sign pattern, N/sample changes, diagnostics, theory/literature mechanism, and binding weakness. Use these rules, not a p-value threshold: `stable` = same sign in every defensible declared variant that ran, magnitude stays within the reported range, no failed key placebo/diagnostic, no unexplained failed run; `mixed` = sign holds but magnitude/precision depends on named variants or holds only in a named subsample/setting, so the claim must be narrowed to that setting; `fragile/unsupported` = sign flips across defensible variants, rests on one specification/sample, fails a key placebo/diagnostic, or a key variant failed. A variant leaves the denominator only for a stated, specification-based defect (e.g. post-treatment control, invalid sample), recorded in the matrix; unfavorable direction or significance is never a reason. Do not select SE by significance. Statistical robustness does not create causal identification.
3. **Revise hypotheses as retrospective.** Under `## Hypotheses`, give revised wording, the class, source run/§9 IDs and rejected candidates with reasons. Keep any original locked hypothesis and PLAN commit/hash intact. For each `stable` candidate, or `mixed` candidate narrowed to its supported setting, append a new §9a row with `origin=post-results`, evidence/limitations and `status=exploratory`; record the dated change in PLAN §12 and LOG. Never write a directional hypothesis for a `fragile/unsupported` candidate; if none qualifies, say so. Never relabel a revision as pre-specified. A separately locked test in a genuinely untouched independent sample/holdout may validate it; the discovery sample alone does not.
4. **Update the manuscript, not just PLAN.** If a defensible candidate survives, revise `# Related literature and hypotheses` in `paper/manuscript.qmd` using the `/ae-write lit` heading, source, citation-check and sole-editor rules; if none survives, report that in results/discussion without fabricating a directional hypothesis. Explicitly introduce any revised hypothesis as exploratory and motivated by the observed pattern, separating prior theory from same-sample evidence. Cite only keys present in the bibliography and verify every cited sentence; report unresolved support instead of inventing a source. Retain original tests and contradictions rather than writing a false ex-ante prediction. Run `Rscript render.R` for HTML preview (no DOCX), report the Viewer path, failures and unresolved evidence.
