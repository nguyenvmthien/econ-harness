Read PLAN.md and LOG.md. `$ARGUMENTS` names sections (abstract, intro, lit, data, method, results, robustness, discussion, conclusion), separated by spaces or commas. For results/robustness, if any §9 ID of that section lacks its output file, stop and tell the user to run `/ae-estimate`.

Wave 1 is requested sections among lit, data, method, results, and robustness. Wave 2 is intro, discussion, conclusion, and abstract; start wave 2 only after wave-1 text is inserted. When a wave has exactly one section, draft inline under the `ae-writer` contract: use its assigned source material and target headings, include required `MODELS:` and `CITED:` lines, and do not invent results. With two or more independent sections, dispatch one `ae-writer` per section in one parallel batch, passing section, target heading(s), §9 rows, and bibliography citekeys. Target headings: intro → `# Introduction`; lit → `# Related literature and hypotheses`; data → `## Data and sample`, `## Variables`; method → `## Empirical specification {#sec-specification}`, `## Identification`; results → `## Descriptive statistics`, `## Baseline results`, `## Heterogeneity and mechanisms`; robustness → `## Robustness`.

You alone edit the manuscript. Replace body under each `HEADING:` line, keeping heading and guidance comments. Add returned `MODELS:` lines to setup chunk if absent. After integrating all prose, inspect the final `paper/manuscript.qmd` and enumerate every citation occurrence as `(citekey, complete sentence including marker, paper/manuscript.qmd:<starting line>)`; a sentence with multiple keys yields one pair per key, and multiline sentences use the line where the sentence starts. Exclude `@tbl-`, `@fig-`, `@eq-`, and `@sec-` references. Keep metadata-only rows (empty `location` and `claim`). For each claim pair, reuse a prior verdict only if citekey, DOI, and the entire sentence match; update its location. Recheck changed/new pairs, and recheck any cached `CANNOT-VERIFY` when `literature/pdf/<citekey>.pdf` now exists. Drop obsolete claim rows. Send pairs in batches of at most ten, grouping by DOI where practical, to `ae-citation-check`; one row per pair. Replace corresponding rows in the CSV. Report NOT-SUPPORTED/CANNOT-VERIFY and `[CITATION NEEDED]` without silently changing claims. Run `Rscript render.R` (HTML only; opens Viewer in RStudio). Render runs manuscript-only audit; do not run full audit here. Append LOG entry.
For each result claim, distinguish any locked original §9a hypothesis from a revised `origin=post-results` hypothesis. If `output/logs/hypothesis_reframe.md` exists, use its evidence matrix when drafting `lit`, results, discussion and abstract; state explicitly when a hypothesis was formulated after examining models, cite appropriate theory, and report conflicting/null checks. If the user requests results-first hypotheses but the report is absent, run the `/ae-hark` sequence before drafting the hypothesis subsection; do not infer robustness from one table. Keep the original PLAN wording and record the revision in §12. Same-sample consistency may motivate a retrospective hypothesis but cannot be presented as independent validation; causal verbs still follow PLAN §11.
When claims trace to `/ae-phacking`, also inspect the linked `output/logs/phacking/<run-id>.md` and the `/ae-hark` evidence matrix before writing; report the fact and breadth of exploratory selection, and do not quote the minimum searched p-value as if it came from one planned test. Do not turn a scratch-only model into a manuscript result before it is reproduced in the project pipeline.
Require the linked `<run-id>.grid.csv` and match cited candidate IDs plus all source/specification fields (`source_path`, `source_object`, `outcome`, `outcome_role`, `exposure`, `exposure_role`, `term`, `proxy_target`, `endogenous_regressor`, `instrument`, `estimator`, `controls`, `fe`, `transform`, `subgroup`, `timing`, `sample_rule`, `se_method`, `clusters`, `declaration_timing`, `variation_type`, `variation_source`, `assignment_rule`, `treated_exposure`, `comparison_group`, `estimand`, `identifying_assumption`, `validation_needed`, `diagnostics`) to the RDS and report. Treat design-only leads as unverified, not findings; `not-run` means incomplete coverage. Never promote a mismatch.
