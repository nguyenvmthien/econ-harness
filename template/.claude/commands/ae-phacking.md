Use `$ARGUMENTS` as research question, data paths, variables, model requests, filters, or exact grid. Standalone scratch search: PLAN, LOG, codebook, data-quality PASS, `/ae-data`, `/ae-estimate`, design/method playbooks are optional context, never prerequisites. FAIL quality reports do not block. Do not invoke `/ae-estimate`, `ae-coder`, `run_all.R`, or `template/R/01_build.R` internally.

All results are EXPLORATORY, not planned tests, independent replication, or causal verdict. Preserve all inputs and attempts. Transform/filter only in memory or scratch copies; never mutate `data/raw`, `data/analysis.rds`, canonical build/sample scripts, PLAN, or manuscript. Exploratory filters need no approval; canonical sample changes remain in the ordinary workflow.

1. **Discover sources and map variable roles.** Explicit file/directory paths take precedence; directories scan recursively. Otherwise use readable `data/analysis.rds`, then independently discover tabular sources under `data/`, including read-only `data/raw/`, excluding `codebook.csv` and `RAW_MANIFEST.csv`. Support RDS data frames and lists of frames (one-based `source_object`; preserve element labels), CSV/TSV via base R, and Parquet/DTA/XLSX only if installed `arrow`/`haven`/`readxl` readers exist. Never implicitly merge sources. Internal paths are project-relative; external paths normalized absolute. Inventory requested/discovered files with reader status and exact errors; continue readable sources. No readable source means precise error and stop, not a `/ae-data` request. Tables with no estimable cells still get an empty grid/report. Missing definitions are “definition unknown”; do not infer meanings from names alone.

For every readable table, inventory all numeric, categorical and date/time columns, missingness, distinct values, ranges, and constant/near-constant status. Use optional PLAN/codebook and explicit user role instructions to identify labels/roles; otherwise treat roles as unknown, not known constructs. Build an expansive role search:
- **Y candidates:** all numeric variables as outcomes, plus user-designated/coded outcome variables.
- **X candidates:** all other numeric variables as exposures, plus user-designated/coded exposures; test every ordered numeric pair so each variable can appear in both roles where estimable.
- **Controls:** no controls and each remaining numeric candidate singly. Add requested control combinations; do not automatically enumerate every possible control subset. Flag possible post-treatment, mechanical overlap, or ratio-component controls; do not suppress requested models.
- **Proxy candidates:** use user/codebook labels or explicitly proxy-like descriptions to identify proxy groups; also test other variables the user designates as proxies. Substitute each candidate proxy separately for Y and X where the declared role is relevant. Record proxy target and rationale/source in the grid; if no target is documented, say target unknown. Do not silently select a proxy by significance.
- **IV candidates:** for each outcome Y, endogenous-regressor candidate X and distinct numeric instrument candidate Z, generate a 2SLS cell when there is enough usable variation. Save exact endogenous regressor and instrument mapping. Report first-stage estimate, partial-F/weak-instrument diagnostics supported by the estimator, sample and inference; flag unavailable diagnostics. Never call an instrument valid based on relevance alone: exclusion restriction is not established by this search. Do not substitute OLS for failed/unavailable IV; preserve failed rows with reason.
- **Potential exogenous variation (separate design-discovery track):** inspect available project documents, metadata, variable names/definitions, panel keys and observed timing/geography/threshold/assignment patterns for candidate sources such as policy or program rollout, eligibility cutoffs, institutional rules, plausibly external shocks, natural events, or predetermined exposure interacted with external shocks. These are leads only, not exogenous variation by assertion. For each lead, record the actual observed/source evidence, source path or exact external reference (or “unverified/missing”), variation type, assignment/timing rule, treated/exposed and comparison units, proposed estimand, identifying assumption, required external validation, and feasible pre-trend/placebo/manipulation/balance/spillover/concurrent-shock checks. Separate facts observed in data from assumptions and conjectures. Do not invent policies, dates, thresholds, instruments, assignment mechanisms, or source citations. Do not label any candidate “exogenous”, “valid IV”, “natural experiment”, or causal; use “potential variation source—unverified” until the assignment mechanism and external source are independently verified. Where no source is evidenced, report no verified candidate and specify what evidence is missing. If the user asks for external search, use attributable primary sources and retain URLs/titles/dates; external evidence still does not validate exclusion or as-if-random assignment by itself. Variation-ledger candidates must be preserved even when not estimable from current data, marked as design-only/not-estimable rather than omitted.
- **Subsamples:** full sample plus each observed level of every categorical subgroup, and explicitly requested filters/intersections. Where time exists, add requested or clearly defined broad period splits; do not manufacture arbitrary sample bins. No automatic cross-product of subgroup variables.
- **Specifications:** identity/log/asinh transforms of Y and X independently; controls unchanged unless requested. Log nonpositive values become missing; record resulting N/sample loss. FE none and available unit/id/firm/bank and period/year columns singly and jointly. Classical OLS, heteroskedastic-robust and unit-clustered inference when supported. For IV use requested IV estimator/inference only. Lags/leads require unambiguous ordered time within unit; otherwise retain failed cells, never use row order as time.

The automatic grid is broad but finite; no candidate-count or p-value cap. User variables/scope narrow only corresponding candidate dimensions; explicit grid replaces automatic grid. Include requested specifications even if unusual or questionable; flag concerns but do not veto estimable cells. Constant/empty/no-variation cells are `not-estimable`. A constant factor exposure has no contrast and is `not-estimable`; each nonconstant requested factor contrast gets its own candidate ID and exact term. Generate and execute large grids in chunks without dropping cells.

2. **Freeze and execute auditable attempts.** Choose collision-free `<run-id>` (`YYYYMMDD_HHMMSS` plus suffix). Write `scratch/ae_phacking_<run-id>.R` and exactly `output/logs/phacking/<run-id>.grid.csv`, `.md`, `.rds`, `.log`; preserve older artifacts. CSV columns exactly:
`candidate_id,source_path,source_object,outcome,outcome_role,exposure,exposure_role,term,proxy_target,endogenous_regressor,instrument,estimator,controls,fe,transform,subgroup,timing,sample_rule,se_method,clusters,declaration_timing,variation_type,variation_source,assignment_rule,treated_exposure,comparison_group,estimand,identifying_assumption,validation_needed,diagnostics`
Use unique stable IDs; blanks mean none. The grid includes executable model cells and design-only variation leads, with explicit status/reason for candidates not estimable using available data. Read the frozen CSV from the script; never re-number/reconstruct. Write the pre-run specification and variation-source inventory before fitting. List prior phacking report IDs/paths as viewed; missing PLAN/LOG/prior reports do not block.

Run `Rscript scratch/ae_phacking_<run-id>.R` from project root. Use fixest/modelsummary where available, explicit `vcov` (`iid`, `hetero`, `~unit` for classical, robust, clustered fixest cases) and the same fitted/inference object for estimates/SE/p-values. Without fixest, classical linear cells may use `stats::lm` with actual documented classical SE; FE may be factor terms. Do not relabel or substitute classical SE for requested robust/cluster inference. Use a real 2SLS estimator for IV, never OLS fallback. Catch per-cell errors; save every grid ID as `done`, `failed`, `not-estimable`, `design-only`, or `not-run` (only interruption). Result rows repeat every grid field and add `formula,n,estimate,se,p_value,status,reason` and available first-stage/diagnostic fields. Save console evidence, completed fitted models named by candidate ID, and RDS exactly `list(run_id=...,grid=...,results=...,ranking=...,models=...)`. Reconcile every grid/result field one-to-one (including role/proxy/IV/variation fields); check estimates and inference against saved model objects. If process aborts, recover durable per-cell evidence, mark unobserved IDs `not-run`, state attempted-since-last-record count is unknown, and label report incomplete; never claim exhaustive coverage.

3. **Rank all directions and variation leads without hiding evidence.** Model direction key includes source path/object, outcome, exposure, estimator, outcome/exposure role, and for IV endogenous regressor/instrument. Rank estimable model directions by minimum observed p-value, candidate ID tie-break; undefined minima last. Report potential variation leads separately by evidence/verification status, never by p-value; distinguish observed facts, assumptions, and missing validation. Include planned-cell counts, tests with p-values, minimum p and best ID for model directions. Retain all estimates, signs, nulls, failures, not-estimable/design-only/not-run cells, inference, N, transforms, proxy mappings, IV first-stage/diagnostics and variation checks/warnings. No alpha threshold or theoretical/methodological veto. Label rankings EXPLORATORY; do not call searched p-values planned, replicated, causal, or proof of instrument validity/as-if-random assignment. Chat may show brief leads but link complete report.
